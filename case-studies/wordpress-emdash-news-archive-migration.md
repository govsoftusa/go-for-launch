# WordPress to EmDash News Archive Migration

<!-- case-study-normalization-reviewed -->

## Purpose

Records the first migration of a WordPress publication to an EmDash-managed
Astro site performed under this toolbox, and the defects that path exposed. The
lessons are generalized in
[WORDPRESS-TO-EMDASH-MIGRATION.md](../WORDPRESS-TO-EMDASH-MIGRATION.md) and
[SOURCE-COMPROMISE-AUDIT.md](../SOURCE-COMPROMISE-AUDIT.md).

## Source and Target

| | |
|---|---|
| Source | WordPress with a commercial theme framework and a magazine child theme |
| Source hosting | Managed WordPress host |
| Media | Offloaded to S3-compatible object storage with CDN delivery |
| Target | Astro with EmDash CMS on an edge platform with a serverless SQL database |
| Site type | Regional culture and entertainment publication, roughly eight years of archive |

## Scope

Approximately 3,600 published articles, a handful of static pages, about 30
categories, several thousand tags, dozens of author bylines, roughly 12,000
media objects, and on the order of 11,800 public routes including archive
pagination.

## Findings

### Finding 1: Offloaded media keys do not match stored content URLs

**Symptom.** Extracted article HTML pointed at CDN URLs that were well formed,
consistent, and returned 404 for every image.

**Root cause.** The media offload plugin stores each object under a key
containing a version segment that the local upload path does not have. Article
bodies contain the pre-offload local path; the plugin substitutes the real key
at render time. Prefixing a CDN hostname onto the stored path therefore produces
a plausible URL that does not exist.

Every offloaded object in the archive was affected, not a subset.

**Detection.** Compare the plugin's stored source path against its stored object
path across the whole table. If they differ for any row, they differ for a
reason, and a path-prefix rewrite is wrong.

**Fix.** Resolve every reference through the offload table. Map each original's
stored upload path to the directory its object occupies, then resolve size
variants by stripping the dimension and scale suffixes to find the family and
re-attaching the requested filename to the resolved directory.

**Reusable check.** After rewriting, request a random sample of resolved URLs
and require all of them to return 200. The failure is invisible in a diff.

### Finding 2: Portable Text conversion is not reproducible

**Symptom.** Two runs of the content generator over identical input produced
different output files.

**Root cause.** The HTML-to-Portable-Text converter generates random block and
span keys.

**Impact.** Non-deterministic output prevents diffing two migration runs,
defeats idempotent import matching, and makes it impossible to prove that a
re-extraction changed nothing.

**Fix.** Post-process each converted document, rewriting every key to a hash of
the document identity and node position, remapping mark definition references in
the same pass. Assert the property by generating twice and comparing checksums.

### Finding 3: Cursor pagination cannot serve a deep numbered archive

**Symptom.** The CMS query interface paginates with opaque keyset cursors. The
source site served numbered archive pages, several hundred on the main archive
and roughly a thousand more across category archives, all indexed.

**Root cause.** Cursor pagination is designed for sequential traversal. A reader
arriving from a search result at a deep page has no cursor and no prior page to
walk from.

**Fix.** Resolve archives in two steps: read the ordered index once, slice it to
the requested page, then fetch that page's entries. The index query is cacheable
and the cost does not grow with page depth.

**Related.** Redirect the `page/1` form to the base route, and return 404 beyond
the end of an archive rather than an empty 200.

### Finding 4: A residual-shortcode stripper corrupts quoted prose

**Symptom.** A first pass that removed all remaining bracket syntax deleted
editorial insertions inside quotations, silently altering article text.

**Root cause.** Square brackets in prose are indistinguishable from shortcode
syntax by shape alone.

**Fix.** Strip only a known list of shortcode names, plus unknown names carrying
`key="value"` attributes. Preserve everything else as literal text and record it
for review. In this corpus that preserved several hundred legitimate bracketed
insertions that the naive pass had removed.

### Finding 5: Theme-generated image variants are unsafe to select automatically

**Symptom.** A delivery-variant selector choosing the largest variant under a
width ceiling produced badly cropped images on portrait photographs.

**Root cause.** The site had changed themes over its life and the media library
retained variants generated by a theme no longer installed, hard-cropped to
fixed aspect ratios.

**Impact.** The output passes automated checks: the files exist, dimensions are
consistent, no request fails. Only visual review catches it.

**Fix.** Restrict variant selection to the platform's core sizes. Report every
attachment with no core variant under the ceiling as needing regeneration on the
source. In this archive that was a small number, in the low tens.

### Finding 6: A legacy 404-redirect table is mostly adversarial traffic

**Symptom.** The legacy redirect table held thousands of rules, exceeding the
edge platform's static redirect limit, and a large fraction pointed at the home
page.

**Root cause.** The plugin records every URL that ever 404'd. On a public site
that is dominated by vulnerability probes. An earlier administrator had
configured them to redirect to the home page rather than 404.

**Fix.** Prioritise structural rules, then content redirects, then shortlink
forms. Spill the overflow into middleware rather than truncating. Drop probe
patterns and record what was dropped, rather than spending redirect budget
returning 301s to scanners and diluting the home page's link profile.

**Related.** Answer removed platform endpoints with 410 rather than 404, so
crawlers stop requesting them.

### Finding 7: The source was compromised

**Symptom.** The active plugin list contained an entry with a machine-generated
directory name carrying an incongruous file extension, presenting itself with a
generic performance-related plugin name.

**Root cause.** An active infection with a payload plugin, a must-use plugin
dropper that reinstalled and reactivated the payload from a base64 copy held in
an option, an external command-and-control endpoint, and a script injected into
pages served to visitors.

**Impact on the migration.** None to the content. Article bodies contained no
injected markup, no administrator account had been created recently, and the
infection was confined to two files and three options. The migrated data was
clean.

**Impact on the process.** The finding changed the cutover plan, added
credential rotation, and produced a new gate. Deleting the payload alone would
not have removed the infection, because the dropper restores it.

**Outcome.** A pre-migration compromise audit is now a documented gate, run
against the backup before extraction.

### Finding 8: The thin-taxonomy-archive heuristic was backwards

**Symptom.** The migration plan proposed marking tag archives under three posts
`noindex`, on the standard reasoning that a near-empty archive is thin,
near-duplicate content competing with the article it lists. The site carried
close to twice as many tags as articles, most holding one or two posts.

**What the data showed.** Across the site's best-performing pages by estimated
organic traffic, tag archives accounted for roughly a tenth of the total, and
about ninety percent of that went to archives holding fewer than three posts.
The proposed rule would have suppressed nearly every tag archive that earned
anything. The two highest earners held two posts and one post.

Not one category archive appeared in the same set, though every category held
well over a hundred posts. By post count, categories were the strong archives.
By traffic, the ordering was reversed.

**Root cause.** Post count measures editorial volume. Indexation value depends
on search demand, and on a publication covering named people, venues and
productions the two are unrelated. The archives that earned ranked for proper
nouns, where an aggregation of every mention of a name is the complete answer to
the query regardless of how many articles it contains.

**Fix.** Suppress only genuinely empty archives. Treat any broader rule as a
decision made with traffic data in hand.

**Reusable lesson.** The duplicate-content concern behind the heuristic was
real; the remedy was wrong. Where a theme renders full post bodies on archives,
rendering excerpts on tag archives removes the duplication without giving up the
ranking. Deindexing spends the ranking to solve a problem that a template change
solves for free.

**Process lesson.** The rule was proposed from structure alone and was only
tested because it was questioned. A policy that changes what a crawler sees
should be derived from measurement, not from a shape in the data.


## Architecture Decisions

| Decision | Reason |
|---|---|
| Read the database rather than the platform's XML export | The export omits the media offload mapping and the legacy redirect tables, and is generated by the source system |
| Two-stage extraction through a neutral dataset | Re-runnable, diffable, and feeds the parity verifier independently of the running site |
| Schema fields for source record ID, permalink and publish date | The seed format carries none of them, and all three are load-bearing for routing and idempotent import |
| Bulk content outside the seed file | The seed is inlined into every build |
| Media left on existing object storage | Avoids re-uploading roughly 12,000 objects and invalidating every indexed image URL |
| Vendored theme stylesheet with a separate overrides file | Keeps a pixel-exact port auditable against the original |
| Tag archives kept indexed regardless of post count; only empty ones suppressed | Traffic data contradicted the thin-content assumption. See Finding 8. |

## Reusable Checks Added

- Resolve every media reference through the offload table, then sample-verify
  the resolved URLs return 200.
- Assert generator determinism by running twice and comparing checksums.
- Fail the build on duplicate content slugs, since slug-resolved CMS routing
  makes one of them unreachable.
- Fail the build on page slugs that collide with routing prefixes or look like
  year segments.
- Build the expected route inventory from the extracted dataset rather than by
  crawling the target, so the check is independent of the thing it checks.
- Pull traffic data for any page family before proposing an indexation change to
  it, rather than inferring value from post count or page shape.
- Probe a deterministic sample of articles rather than all of them.

## Still Open

Comment bodies were not imported. Multi-author bylines, scheduled and private
post states, custom post types, custom field plugins and multisite were not
exercised. The standard production gates, including native mobile Safari testing
and the performance audit, remain to be run against a deployed candidate.
